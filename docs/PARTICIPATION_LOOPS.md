## 1. Зачем этот контур

Отдельный формат personal discovery для Threads: не просто пост, который читают, а механика, которую человек может повторить на себе и принести результат обратно в ветку.

Ключевая идея: **вирусность не является типом контента и не гарантируется.** Мы проектируем participation loop — низкое трение, персональный результат, визуальная демонстрация и естественная причина поделиться.

Это не заменяет обычный личный Threads и не превращает его в AI-контент-фабрику.

## 2. Наблюдаемый паттерн

Два сильных примера одного класса механики:

### Pattern A — Personal identity transform

Пользователь копирует короткий промпт вроде:

> «На основе всего, что ты обо мне знаешь, заполни обе стороны этого контейнера разными предметами, которые мне подходят».

Вход: промпт + при необходимости изображение.

Выход: уникальная визуализация самого человека. Главный социальный объект — не исходный пост, а **собственный результат участника**.

### Pattern B — Pet → physical-looking artifact

Пользователь загружает фото питомца и получает персональный papercraft / шаблон фигурки.

Вход: одно фото + готовый промпт.

Выход: визуальный артефакт, который хочется показать другим и сравнить с результатами других участников.

Общий механизм обоих паттернов:

```text
вижу необычный результат
→ понимаю, что могу сделать такой же про себя
→ копирую готовую инструкцию
→ получаю персональный артефакт
→ хочу показать результат
→ возвращаюсь в ветку / отправляю друзьям / делаю ремикс
```

## 3. Anatomy of a strong challenge

Хороший challenge должен максимально закрывать семь свойств:

1. **Zero-friction** — начать можно за 10–30 секунд.
2. **Identity** — результат относится к самому человеку, его питомцу, фото, привычкам, вкусу или истории.
3. **Transformation** — до запуска понятно, что получится заметное превращение.
4. **Visual payoff** — результат считывается без длинного объяснения.
5. **Curiosity gap** — человеку интересно увидеть именно *свой* вариант.
6. **Shareability** — результат не стыдно и не скучно показать публично.
7. **Remixability** — механику легко повторить с новым объектом, стилем или условием.

### Быстрый score

Каждое свойство: `0 / 1 / 2`.

- `0` — отсутствует;
- `1` — есть, но слабо;
- `2` — выражено сильно.

Максимум: `14`.

- `< 9` — не публиковать как challenge;
- `9–11` — можно быстро протестировать;
- `12–14` — приоритетный кандидат.

Score — фильтр, а не обещание охвата.

## 4. Базовая формула публикации

```text
HOOK
→ 1 фраза: что человек сможет получить
→ минимальная инструкция
→ PROMPT / действие
→ пример результата
→ просьба показать свой результат
```

Не добавлять длинное объяснение AI, историю технологии или несколько CTA. Чем больше инструкция похожа на туториал, тем выше трение.

### Нормальная роль автора

Максим пишет hook и подачу сам. AI может помогать:

- проектировать механику;
- делать prompt engineering;
- собирать визуальные варианты;
- тестировать устойчивость результата;
- анализировать метрики;
- хранить библиотеку паттернов.

AI не должен автоматически писать личный голос Максима или массово генерировать посты ради частоты.

## 5. Challenge lifecycle

```text
trend / observation / собственная идея
→ extract mechanism
→ score
→ prototype prompt
→ 3–5 test generations
→ simplify instruction
→ owner writes hook
→ publish in Threads
→ measure 1h / 6h / 24h / 72h
→ classify
→ remix / scale / archive
```

Важно: копируем **механику участия**, а не чужой текст, конкретный визуал или формулировку.

## 7. Что считать настоящим успехом

Главная метрика не `likes` сама по себе.

Для participation format важнее:

- количество людей, реально повторивших механику;
- ответы с собственным результатом;
- пересылки / shares;
- repost / quote с собственным вариантом;
- profile visits и followers delta;
- появление самостоятельных ремиксов;
- сохранение скорости распространения после первого импульса.

### Рабочая классификация

**Winner** — challenge даёт заметно больше participation/shares, чем обычные посты, и механику можно повторить без ощущения копии.

**Interesting** — reach высокий, но люди в основном потребляют результат, а не участвуют.

**Dead end** — требует слишком много шагов, результат нестабилен или людям нечего показывать другим.

Пороговые цифры задаются только после накопления собственной базы, а не берутся из чужих аккаунтов.

## 8. Библиотека challenge families

### A. Identity projection

AI визуализирует характер / вкус / роль / внутренний мир пользователя.

Примеры механик:

- заполнить контейнер предметами, которые подходят человеку;
- показать «мой цифровой рабочий стол через 10 лет»;
- собрать комнату / набор / витрину по тому, что AI знает о человеке;
- превратить профиль человека в музейную экспозицию.

### B. Personal photo transform

Одно фото пользователя → новый понятный визуальный объект.

Примеры:

- фигурка / игрушка / упаковка;
- персонаж оригинальной вселенной;
- low-poly / papercraft;
- коллекционная карточка;
- «если бы я был…» с чётким визуальным правилом.

### C. Pet transform

Фото питомца → артефакт, предмет, персонаж, шаблон, модель.

Сильная сторона: эмоциональная привязка + высокая готовность делиться результатом.

### D. Comparison / puzzle

AI создаёт пару визуалов, где аудитория должна найти отличия, выбрать версию или угадать преобразование.

Здесь participation происходит прямо внутри Threads без обязательного перехода в нейросеть.

### E. Social mirror

Промпт заставляет AI дать визуальный ответ на вопрос «каким он видит меня / мой стиль / мою работу / мой год».

Сильная сторона: любопытство к собственной интерпретации.

### F. Remix chain

Первый результат становится входом следующего участника или следующего шага.

Использовать осторожно: каждый дополнительный шаг повышает трение.

## 9. Anti-patterns

Не делать challenge, если:

- без длинной инструкции невозможно начать;
- нужен платный или редкий инструмент без очевидной причины;
- результат у большинства будет почти одинаковым;
- hook обещает больше, чем реально выдаёт модель;
- визуал красивый, но персонализация фиктивна;
- нужно пять приложений и ручная обработка;
- participation строится на спаме, обязательных тегах или искусственных «отметь 5 друзей»;
- AI пишет за Максима личную подачу;
- мы клонируем чужой текст/визуал вместо механики.

## 10. Relation to Content OS

Participation challenge — **формат personal discovery**, а не новый канал и не отдельная медиа-вертикаль.

По умолчанию:

```text
Threads challenge
→ replies / participant artifacts
→ analytics
→ winner library
→ optional Telegram continuation only if there is real deeper material
```

Не каждый winner переносится в Telegram или на сайт.

## 11. Future automation boundary

Если формат подтвердится на собственной статистике, в `agents` можно добавить `Challenge Lab`:

```text
manual trend signal / URL / screenshot
→ mechanism extractor
→ novelty + friction + participation scorer
→ challenge brief
→ prompt prototype
→ human test
→ owner approval
→ experiment log
```

Что **не** автоматизировать:

- финальный личный hook;
- решение публиковать;
- автопостинг непроверенного prompt;
- массовое копирование трендов.

Первый Gate перед разработкой: минимум **5 опубликованных challenge experiments**, из них минимум **2 с явно повышенным participation/share behaviour** относительно обычных постов.

До этого достаточно ручного процесса + документации.
