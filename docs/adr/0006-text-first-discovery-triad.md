# ADR 0006 — Text-first discovery triad: Threads + Bluesky + X → Telegram

- **Статус:** Accepted
- **Дата:** 2026-09-18
- **Область:** личный авторский контур Максима, text-first social distribution, переход аудитории в Telegram
- **Связанные документы:** `docs/MEDIA_TOPOLOGY.md`, `docs/CHANNELS.md`, `docs/CONTENT_OS.md`, ADR 0004

## Контекст

Текущая медиатопология ставила личный Telegram Максима в позицию главного живого author feed, а остальные социальные площадки рассматривала в основном как адаптированные поверхности.

Фактический авторский формат Максима оказался другим: короткий текст, мысль, наблюдение, история, юмор, вывод или диалог без обязательного фотоконтента. Для этого формата логичнее использовать несколько text-first discovery-платформ параллельно, не создавая три независимые редакции и три отдельных контент-плана.

Новая задача верхнего слоя — максимизировать discovery при минимальной операционной нагрузке. Следующий слой — перевод части аудитории в личный Telegram, где связь с автором глубже и контент может быть длиннее и менее алгоритмически зависимым.

## Решение

### 1. Discovery triad

Основной text-first discovery layer состоит из трёх платформ:

1. **Threads**;
2. **Bluesky**;
3. **X (Twitter)**.

Они рассматриваются как один логический publishing layer, а не как три независимые редакции.

Один авторский пост может быть опубликован на всех трёх площадках в практически идентичном виде.

Это является осознанным исключением из общего правила против механического cross-posting: исключение действует только для коротких text-first авторских постов внутри discovery triad.

Обязательная платформенная адаптация не требуется. Она допускается только когда:

- этого требует техническое ограничение платформы;
- меняется ссылка/CTA;
- формат треда или цитирования требует другой структуры;
- доказано, что конкретная адаптация существенно улучшает результат без дополнительной редакционной нагрузки.

### 2. Автор остаётся источником текста

Текст поста пишет Максим.

AI/automation могут:

- публиковать;
- планировать;
- сохранять архив;
- добавлять технические метаданные;
- собирать статистику;
- отслеживать ссылки и переходы;
- помогать искать старые публикации.

По умолчанию AI не должен переписывать пост «под площадку», генерировать авторскую мысль вместо Максима или превращать личный стиль в контент-фабрику.

### 3. Telegram — relationship / retention layer

Личный Telegram Максима становится не исходной точкой каждого короткого поста, а следующим уровнем авторской системы.

Его функция:

- удерживать наиболее заинтересованную аудиторию;
- давать продолжения и контекст;
- публиковать более длинные мысли;
- собирать несколько наблюдений в одну запись;
- показывать проекты, разработку и решения глубже;
- давать редкие и уместные переходы на продукты/сайт.

Telegram не должен автоматически зеркалировать каждый пост из Threads/Bluesky/X.

Причина подписаться на Telegram должна быть самостоятельной: глубина, продолжение, контекст, архив мысли и более тесная связь с автором.

### 4. Traffic flow

Базовая схема:

```text
                    Максим
                      │
                авторский текст
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
       Threads     Bluesky     X (Twitter)
          │           │           │
          └───────────┼───────────┘
                      ▼
                 Telegram
          relationship / retention
                      │
                      ▼
              сайт / проекты
          Pro-leads / Tender Audit
```

На текущем этапе основной downstream destination из discovery triad — личный Telegram.

Дополнительные платформы не подключаются только ради присутствия.

### 5. CTA policy

Discovery triad не превращается в постоянную рекламную воронку.

Правила:

- основной контент существует сам по себе;
- постоянный CTA в каждом посте запрещён;
- Telegram указывается в профилях/ссылках и упоминается в постах только естественно;
- прямой переход в Telegram используется, когда там реально есть продолжение, разбор или дополнительная ценность;
- продуктовые CTA идут ниже по воронке и не должны конкурировать с CTA в Telegram в одном коротком посте.

### 6. Что пока не является ядром

Instagram, Facebook, VK, MAX, LinkedIn, TenChat, VC.ru, Дзен и видео-платформы не входят в обязательный ежедневный publishing layer.

Они могут использоваться позже как отдельные surfaces при доказанной функции, но не должны создавать новую редакционную нагрузку раньше времени.

Instagram отдельно рассматривается как возможный визуальный слой в будущем, а не как обязательная часть текущего text-first контура.

### 7. Measurement

Для discovery triad измеряются отдельно по платформам:

- показы/охват;
- profile visits;
- replies/reposts/quotes;
- качественные диалоги;
- переходы в Telegram;
- подписки в Telegram, насколько это технически атрибутируемо;
- повторяемость сильных тем.

Главная системная метрика не равна просмотрам одного поста. Важнее способность triad стабильно приводить новую релевантную аудиторию в Telegram без роста редакционной сложности.

### 8. Automation boundary

В будущем допустим единый publisher:

```text
author writes once
→ review by author
→ publish to Threads + Bluesky + X
→ archive
→ collect metrics
```

Автоматизация не является условием запуска модели. Сначала подтверждается ручной workflow и полезность трёх площадок.

Техническая реализация publisher относится к `agents`/publication runtime и должна проектироваться отдельным изменением.

## Что этот ADR заменяет

ADR 0006 не отменяет author-first принцип ADR 0004 и Product Social Gate.

Он заменяет только следующие положения прежней operating model:

- Telegram больше не является обязательным primary home для каждого короткого авторского поста;
- внешние text-first платформы больше не считаются только вторичной адаптированной дистрибуцией;
- запрет на механический cross-posting получает узкое исключение для Threads + Bluesky + X;
- верхний author acquisition layer теперь явно отделён от Telegram retention layer.

## Последствия

Положительные:

- один авторский текст получает три независимых discovery-поверхности;
- не требуется три контент-плана;
- сохраняется естественный стиль автора;
- Telegram получает ясную функцию вместо роли ещё одного зеркала;
- система масштабируется технически без необходимости масштабировать производство контента.

Цена решения:

- одинаковый пост может работать по-разному на трёх алгоритмах;
- часть платформенных оптимизаций сознательно не используется на первом этапе;
- понадобится раздельная аналитика источников;
- Telegram должен давать дополнительную ценность, иначе конверсия из discovery layer будет слабой.

## Инвариант

> Максим пишет один сильный text-first материал. Threads, Bluesky и X распространяют его в трёх независимых discovery-графах. Telegram углубляет связь с аудиторией, а не дублирует верхний слой.
