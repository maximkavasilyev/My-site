# ADR 0003 — Признание `agents` техническим runtime существующих каналов

- **Статус:** Accepted
- **Дата:** 2026-08-06
- **Связанные документы:** `docs/adr/0002-editorial-channel-network.md`, `docs/EDITORIAL_NETWORK.md`, `docs/MEDIA_SYNC.md`, `docs/CHANNELS.md`

## Контекст

Параллельно с принятием ADR 0002 в этом репозитории владелец вёл отдельную сессию в репозитории `agents` (`maxight-agent-platform`), где технически реализована durable-платформа для Telegram intake, approval и публикации: Gate G1–G3 пройдены, Gate G4 (publishing sub-gate) пройден с живым подтверждением — воркер `agents-publisher` реально публикует одобренные материалы в три существующих Telegram-канала (`t.me/proleads_ru`, `t.me/tenderaudit`, `t.me/maxightAI`) через бота `@publisher_agent_bot`.

ADR 0002 в разделе «Не разрешено этим ADR» прямо запрещает до соответствующего Media Gate: «писать Telegram-бота или оркестратор», «подключать токены публикации», «включать автопостинг». На момент принятия ADR 0002 эти ограничения были сформулированы в расчёте на три *новых* тематических канала (новости нейросетей, разработка с AI, AI-инструменты), которые действительно ещё не существуют и остаются на Gate M0.

Однако формулировка ADR 0002 не делает различия между «ещё не запущенными новыми каналами» и «уже существующими продуктовыми/личными каналами, для которых бот и автопубликация уже действуют и утверждены владельцем». Из-за этого текст ADR 0002 буквально противоречит уже действующей инфраструктуре `agents`, хотя по факту это разные предметы: три уже работающих канала не входят в тематическую редакционную сеть, описанную в ADR 0002 (см. `EDITORIAL_NETWORK.md`, раздел 1: сеть — это личный канал + 3 новых тематических канала + сайт + продуктовые каналы как отдельная категория).

## Решение

1. Репозиторий `agents` признаётся техническим runtime персональной медиасистемы для **уже существующих** publication targets: `proleads_ru`, `tenderaudit`, `maxightAI`. Для этих трёх каналов автоматизация (Telegram control bot, deterministic publisher, durable approval workflow) действует и не требует последовательного прохождения Media Gates M0–M6 — они не относятся к тематической редакционной сети ADR 0002.
2. Ограничения ADR 0002 («нет бота», «нет токенов», «нет автопостинга» до соответствующего Gate) относятся исключительно к **трём новым тематическим каналам**, описанным в ADR 0002 (новости нейросетей, разработка с AI, AI-инструменты), и к личному каналу Максима. Пока эти каналы не созданы и Gate не открыт, `agents` не подключает их как publication target.
3. `agents` добавляется как четвёртый слой в sync-контракт `MEDIA_SYNC.md`: технический runtime, исполняющий approval и publishing для утверждённых publication targets. Notion остаётся источником стратегии, GitHub (оба репозитория) — versioned canon, `agents` — исполняющий слой для уже утверждённых каналов.
4. Расширение `agents` на новые тематические каналы из ADR 0002 допускается только после того, как соответствующий канал пройдёт Gate M1 (ручной пилот) в терминах `EDITORIAL_NETWORK.md`, и это будет отдельным явным решением владельца, а не автоматическим следствием готовности кода в `agents`.

## Рассмотренные варианты

### Вариант A — откатить автоматизацию в `agents` до Gate M4

Отклонён. Три уже действующих канала не являются частью тематической редакционной сети из ADR 0002 — откат автоматизации для них не требуется этим ADR и создал бы регресс без причины.

### Вариант B — переписать ADR 0002 задним числом

Отклонён. ADR — исторический документ; вместо правки принятого решения фиксируется отдельный ADR, уточняющий его границы.

## Последствия

### Положительные

- Устранено буквальное противоречие между ADR 0002 и уже работающей инфраструктурой.
- Чётко разграничены уже действующие каналы и будущая тематическая сеть — Gates ADR 0002 сохраняют полную силу для новых каналов.
- `agents` явно вписан в трёхслойный (теперь четырёхслойный) sync-контракт, а не остаётся вне него.

### Отрицательные

- Требуется поддерживать актуальность списка publication targets, для которых `agents` уже является runtime, синхронно между `agents/docs/architecture/OPEN_QUESTIONS.md` и `MEDIA_SYNC.md` здесь.

## Не разрешено этим ADR

- автоматически подключать новые тематические каналы к `agents` без прохождения Gate M1 по `EDITORIAL_NETWORK.md`;
- изменять правила Gates M0–M6 или Sync Gates S0–S3 из ADR 0002;
- переносить продуктовые данные Pro-leads/Tender Audit в медиасистему.

## Условия пересмотра

Пересматривается, если новый тематический канал готов к Gate M1 и требует подключения к `agents`, либо если появится техническое решение вести publication targets только через один из репозиториев.
