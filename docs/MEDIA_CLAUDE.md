# MEDIA_CLAUDE.md — Правила медиа-контура репозитория

> Этот файл читается вручную при работе над медиа/контентом (не автозагружается, в отличие от
> корневого `CLAUDE.md`). Корневой `CLAUDE.md` остаётся приоритетным для правил репозитория и
> кода сайта в целом; этот файл — дополнение специально для контент-операций.

## Что это за контур

Этот репозиторий — одновременно сайт Максима (см. корневой `CLAUDE.md`, `ARCHITECTURE.md`) и
хранилище канона его персонального медиа: соло-предпринимателя, разработчика, архитектора систем
и AI-специалиста.

Медиа документирует реальную работу над продуктами и поддерживает личный бренд, Pro-leads, Tender Audit и будущие сервисы.

## Перед любой задачей

Прочитать:

1. `BRAND.md`
2. `MEDIA_ARCHITECTURE.md`
3. `CONTENT_OS.md`
4. `EDITORIAL_GUIDE.md`
5. `ECOSYSTEM.md`
6. документы конкретного продукта, если материал связан с ним.

## Жёсткие правила

1. Не придумывать опыт, цифры, кейсы, отзывы и результаты.
2. Не смешивать Pro-leads и Tender Audit.
3. Каждый материал имеет один основной тезис.
4. Сначала определить тип: expert / product / case / research / note.
5. Экспертный материал не обязан иметь CTA.
6. Продуктовый CTA ведёт только на релевантный продукт.
7. Не публиковать автоматически без проверки пользователя.
8. Не добавлять новый канал или сложную автоматизацию без архитектурного решения.
9. Факты, выводы и гипотезы разделять.
10. При нехватке данных явно указать, чего не хватает.

## Рабочий порядок

При обработке идеи:

1. определить тип;
2. сформулировать тезис;
3. определить аудиторию;
4. выбрать канонический канал;
5. проверить связь с продуктом;
6. перечислить недостающие данные;
7. создать outline;
8. только после подтверждения писать финальный материал.

## Структура

`/content/posts` и `/content/pages` — уже занятые сайтом каталоги (рендерятся Next.js, схема
фронтматтера из TECH_SPEC.md). Рабочий пайплайн медиа живёт отдельно, в `/media/`:

```text
/media/inbox
/media/backlog
/media/drafts
/media/canonical
/media/published
/media/archive
/media/research
/media/assets
/media/analytics
```

Подробности и связь с `/content/posts/` — в `CONTENT_OS.md`, п.19.

## Архитектурные изменения

Если задача противоречит канону, остановиться и сообщить об этом. Не менять правила точечно под один пост или текущий тренд.
