# ROADMAP.md — план развития

Статус: **v3.0 / current**.

Принцип: **результат → спрос → оплата → автоматизация → масштабирование**. Следующий этап не начинается по календарю; он открывается только доказательствами предыдущего.

Product/Site Gates, Media Gates и Sync Gates — разные шкалы. Прохождение одной не открывает автоматически другую.

## 0. Текущее реализованное состояние

Статический сайт завершён как техническая база:

- [x] Next.js App Router и Tailwind;
- [x] статический экспорт и `trailingSlash: true`;
- [x] страницы `/`, `/about`, `/projects`, `/blog`, `/blog/[slug]`, `/contact`;
- [x] внутренний `/design-system`;
- [x] Markdown-контент и build-time validation;
- [x] CTA через `cta_quote`;
- [x] nginx deployment contract;
- [x] CI, lint, build и Playwright e2e;
- [x] sitemap, robots, RSS и OG;
- [x] accessibility fixes и mobile navigation;
- [x] базовый analytics scaffold, выключенный по умолчанию;
- [x] Notion Canon v2 синхронизирован с GitHub через PR #1;
- [x] архитектурный cleanup после синхронизации;
- [x] тематическая редакционная сеть описана в `EDITORIAL_NETWORK.md`;

Текущая реализация не содержит БД, auth, payments, account, CMS, backend API, comments, workers, queues, scheduler, publishing runtime или автопостинг.

Тематические каналы и мультиплатформенная дистрибуция являются approved direction, а не реализованной системой.

## 2. Gate 0 — экспертное ядро сайта

Цель: доказать, что сайт и контент создают устойчивую ценность и приводят целевую аудиторию.

- [x] уточнить главную страницу и два маршрута: бизнес / создатели;
- [ ] опубликовать устойчивый набор бесплатных материалов;
- [ ] подготовить исследования как редакционный формат без коммерческого backend;
- [ ] измерять целевые переходы, подписки, ответы и возвраты;
- [ ] сохранить Pro-leads и Tender Audit отдельными продуктами;
- [ ] не расширять платформу при отсутствии устойчивого интереса.

## 3. Gate 1 — один платный материал вручную

Цель: проверить конкретную проблему и готовность платить до разработки commerce layer.

- [ ] выбрать одного целевого пользователя и одну проблему;
- [ ] провести исследование с разделением фактов, источников, опыта, выводов и гипотез;
- [ ] создать полезную бесплатную версию;
- [ ] описать платный результат и состав;
- [ ] проверить оффер и цену;
- [ ] получить реальные оплаты простым способом;
- [ ] доставить материал вручную;
- [ ] зафиксировать причины покупки, отказа и повторного спроса;
- [ ] посчитать стоимость создания и поддержки.

Стартовый ценовой ориентир не является каноном и проверяется рынком.

## 4. Gate 2 — коммерческое подтверждение

Переход дальше разрешается только при наличии:

- ориентировочно 5–10 платежей от целевой аудитории вне близкого окружения;
- понятной оплачиваемой проблемы;
- ясной причины, почему бесплатного материала недостаточно;
- признаков повторного спроса;
- приемлемой стоимости создания и поддержки;
- доказательства, что ручная доставка стала ограничением подтверждённого спроса.

Если Gate не пройден, меняются тема, аудитория, оффер или цена. Backend не строится ради спасения гипотезы.

## 5. Gate 3 — Account & Commerce MVP

Только после отдельной технической спецификации и ADR:

- [ ] бесплатная регистрация;
- [ ] email/magic-link или другой отдельно выбранный auth;
- [ ] каталог конкретных платных материалов;
- [ ] разовые покупки;
- [ ] purchase/access state;
- [ ] кабинет со списком покупок и доступных материалов;
- [ ] бессрочный доступ к купленной версии по заявленным условиям;
- [ ] скачивание приложений;
- [ ] необходимые email-уведомления;
- [ ] чеки, возвраты, политика доступа и юридические страницы;
- [ ] logging, backup, security review и operational runbook.

Не входят: subscription, saved content, personalization, comments, community и marketplace.

## 6. Gate 4 — удержание

Функции выбираются только из наблюдаемого поведения:

- сохранённое;
- подписки на темы и обновления;
- подборки;
- история и персонализация;
- небольшие прикладные инструменты;
- тематические комплекты материалов.

Подписка вводится только при доказанной регулярной ценности и повторном потреблении.

## 7. Gate 5 — обсуждения и community

- [ ] комментарии под материалами;
- [ ] ручная модерация;
- [ ] правила и процессы разрешения конфликтов;
- [ ] закрытые обсуждения вокруг конкретного платного продукта;
- [ ] отдельное community-пространство только при устойчивом возвращающемся ядре.

Форум, уровни, рейтинги и геймификация заранее не проектируются.

## 8. Gate 6 — курируемый marketplace

- [ ] выбрать одну категорию и проблему поиска;
- [ ] собрать вручную курируемый каталог;
- [ ] проверять участников;
- [ ] протестировать affiliate, paid listing или lead generation;
- [ ] вводить отзывы только после подтверждённого взаимодействия;
- [ ] измерить спрос, предложение, доверие и стоимость модерации.

Seller dashboards, commissions, disputes и встроенные расчёты между сторонами — отдельный поздний Gate.

## 9. Gate 7 — PWA и native apps

Native apps рассматриваются только если:

- Web App используется регулярно;
- есть подтверждённое мобильное ограничение;
- PWA не закрывает потребность;
- стоимость разработки и поддержки оправдана.

Telegram Mini App не является основным клиентом. Он может появиться только как лёгкая точка входа, уведомления или узкий изолированный сценарий.

- [x] запретить немедленный автопостинг.

Следующее действие: выбрать финальные названия и подготовить ручной пилот.

## M1 — ручной пилот

Цель: проверить границы каналов и реальную стоимость производства до автоматизации.

- [ ] проверить доступность названий и Telegram username;
- [ ] утвердить визуальную систему сети;
- [ ] создать каналы или запускать их последовательно;
- [ ] подготовить по 10–20 стартовых материалов на активный канал;
- [ ] определить ручной публикационный календарь;
- [ ] вести единый реестр контентных объектов;
- [ ] каждый материал подтверждать вручную;
- [ ] измерить время исследования, редакции, визуала и публикации;
- [ ] зафиксировать условия остановки каждого канала.

На M1 не создаются publishing bot, scheduler, queue или автоматический cross-posting.

## M2 — повторяемый процесс

Gate открывается после минимум 30 дней устойчивой ручной работы.

Требования:

- [ ] каналы не дублируют друг друга;
- [ ] понятен минимальный устойчивый ритм;
- [ ] источник контента не исчерпывается;
- [ ] редакционные шаблоны дают стабильное качество;
- [ ] стоимость производства приемлема;
- [ ] есть содержательные сигналы аудитории;
- [ ] реестр и аналитика ведутся без пропусков;
- [ ] понятны материалы, которые не следует публиковать.

## M3 — агентные черновики

Цель: снизить ручную нагрузку без передачи агентам права публикации.

- [ ] агент поиска кандидатов;
- [ ] дедупликация;
- [ ] ranking по значимости и каналам;
- [ ] source pack с первичными источниками;
- [ ] фактчекинг и маркировка неопределённости;
- [ ] черновик основного материала;
- [ ] адаптации под вторичные каналы;
- [ ] сценарии Reels/Shorts;
- [ ] обязательное подтверждение владельца;
- [ ] измерение доли принятых и отклонённых черновиков.

## M4 — очередь и расписание

Разрешается только для уже утверждённых материалов.

- [ ] публикационный реестр со статусами;
- [ ] очередь;
- [ ] расписание;
- [ ] audit log;
- [ ] retry;
- [ ] ручная остановка;
- [ ] отмена до публикации;
- [ ] контроль дублей;
- [ ] безопасное хранение credentials вне Markdown и Notion;
- [ ] отдельная техническая спецификация и ADR.

## M5 — ограниченная автопубликация

Допускается только для allowlist-форматов и источников.

- [ ] явно перечислить допустимые форматы;
- [ ] исключить авторскую позицию, спорные новости, рекламу и продуктовые публикации;
- [ ] определить confidence thresholds;
- [ ] сохранять источники и audit trail;
- [ ] включить мониторинг ошибок;
- [ ] иметь rollback/удаление;
- [ ] проводить регулярный выборочный review;
- [ ] автоматически останавливать контур при расхождении Notion/GitHub canon.

## M6 — мультиплатформенность

Подключать платформы по одной:

- [ ] MAX;
- [ ] VK;
- [ ] Instagram/Reels;
- [ ] YouTube Shorts;
- [ ] YouTube long-form;
- [ ] другие площадки только по отдельному решению.

Для каждой площадки до запуска определить:

- аудиторию;
- функцию;
- нативный формат;
- источник контента;
- метрику;
- стоимость поддержки;
- условие остановки;
- правила CTA и ссылки;
- юридические и платформенные ограничения.

# Sync Roadmap

## S0 — ручная дисциплина

**Статус:** текущий обязательный режим.

- [x] определить роли Notion, GitHub и local;

## S1 — read-only аудит

- [ ] агент сравнивает документы и ссылки;
- [ ] ищет страницы Notion без GitHub reference;
- [ ] ищет merged PR без обновления Notion;
- [ ] ищет локальные commits, не отправленные в remote;
- [ ] формирует отчёт без записи.

## S2 — агентная подготовка изменений

- [ ] агент создаёт draft-изменение;
- [ ] создаёт ветку;
- [ ] обновляет Markdown и ADR;
- [ ] открывает PR;
- [ ] предлагает patch для Notion;
- [ ] не merge и не меняет Gates самостоятельно.

## S3 — безопасные служебные записи

После устойчивой работы агент может обновлять:

- [ ] `github_pr`;
- [ ] `github_commit`;
- [ ] `last_synced_at`;
- [ ] `sync_state`;
- [ ] опубликованные URL;
- [ ] технический статус проверки.

Стратегия, позиционирование, Gate и product boundaries остаются ручными решениями владельца.

## Архитектурная стратегия

- статический сайт сохраняется до доказанной backend-необходимости;
- первая backend-форма — модульный монолит;
- publishing runtime не объединяется автоматически с runtime продуктов;
- providers и инфраструктура выбираются перед соответствующим Gate;
- shared services допускаются после одинаковой доказанной потребности минимум в двух продуктах или контурах;
- каждый крупный переход сопровождается ADR, migration plan, rollback и метриками;
- продукты не объединяются ради удобства инфраструктуры;
- редакционная сеть не получает отдельный backend до M4 и отдельной спецификации;
- локальная рабочая копия не является каноном.

## Открытые вопросы владельца

- Telegram username;
- запускать три канала одновременно или последовательным пилотом;
- какая тема станет первым пилотным каналом;
- какой минимальный ритм допустим без потери качества;
- нужны ли лицо Максима или единый графический знак на аватарках;
- первый тестовый платный материал сайта;
- критерии успешного Gate 0 сайта;
- критерии успешного M1 тематической сети.
